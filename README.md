# Diarized Transcription

감사 면담·회의 녹음을 **화자별 녹취록**으로 만드는 개인용 웹앱입니다. 녹음 출처는 세 가지입니다:
**Plaud**(전사 스크립트 + 음원), **소니 녹음기**(ICD-TX660 등), **휴대폰·기타 기기**(녹음 앱·통화 녹음 m4a 등).
(저장소 이름 Plaud-Booster와 주소는 예전 이름 그대로입니다.) **GitHub Pages 주소를 열면 바로 쓰고, 음원과 전사는 PC 밖으로 나가지 않습니다.**
전사(Whisper turbo)와 화자 맞히기(CAM++)가 모두 브라우저 안(WebAssembly)에서 돌아갑니다.

**주소:** https://kgcaudit.github.io/Plaud-Booster/

「새 작업」은 **1. 녹음 출처 → 2. 할 일** 순서로 고릅니다.

| 녹음 출처 | 할 일 | 하는 일 |
|---|---|---|
| Plaud 녹음 | **빠진 구간 채우기** | Plaud 전사가 녹음 중간에 끊겼을 때, 끊긴 지점부터 녹음 끝까지 전사하고 Plaud 이름으로 화자를 맞힙니다. |
| | **잘못된 구간 다시 전사** | 잘못 전사된 구간(시작~끝)만 다시 전사합니다. |
| | **목소리 기준만 등록** | Plaud에 이름 붙은 사람의 목소리 기준만 만듭니다. |
| 소니 녹음기 · 휴대폰·기타 기기 | **화자 나누기·전사**(권장) | 비슷한 목소리를 먼저 묶고(Speaker 1, 2…), 대표 구간을 들어 이름을 붙인 뒤 전사합니다. 휴대폰은 「통화 녹음(두 사람)」 선택 가능. |
| | **저장된 목소리로 바로 맞히기** | 이름 붙이기 없이 저장된 목소리 기준 중 가장 닮은 사람으로 판정합니다. |

같은 회의를 Plaud와 다른 기기로 함께 녹음한 경우 두 녹음을 합치는 기능은 준비 중입니다.

여러 파일은 녹음 시각 순으로 자동 정렬합니다. 녹음 시각은 **파일 이름**(소니 `251009_1430.mp3`, 갤럭시 통화 녹음 `…_251009_143000.m4a`)
→ **파일 안 정보**(m4a 생성 시각) → **저장 시각 − 길이**(추정) 순으로 찾습니다. 휴대폰 m4a(AAC)도 MP3처럼 60초씩 잘라 풀어 긴 녹음에서도 메모리가 안전합니다.
작업마다 「참석자에게 녹음 사실을 알렸음」을 표시할 수 있고, 통합본 머리에 녹음 출처·할 일·녹음 고지가 적힙니다.

처리 결과는 검수 화면에서 구간마다 들어 보며 화자·문장을 고치고, Plaud 전사와 합친 **통합본(TXT·CSV)** 으로 내려받습니다.

### 화자 나누기·전사(소니·휴대폰 — 화자 먼저 → 이름 → 전사)

1. 「새 작업 → 출처(소니 녹음기 또는 휴대폰·기타) → 화자 나누기·전사」에서 녹음 파일을 고릅니다(여러 개 가능).
   참석자(선택)를 고르면 그 사람들의 목소리 기준으로만 이름을 추천하고, 참석 인원(선택)은 묶음이 지나치게 많아지지 않게 하는 데만 씁니다.
2. 목소리 특징만 먼저 계산해 비슷한 목소리를 묶습니다(전사보다 훨씬 빠름). 끝나면 작업이 **「이름 대기」** 가 됩니다.
3. **화자 이름 붙이기**: 묶음마다 대표 구간을 ▶로 들어 보고 이름을 넣습니다. **같은 이름을 붙이면 한 사람으로 합쳐집니다.**
   저장된 목소리 기준과 닮은 묶음에는 「추천」이 뜹니다(확정은 사람이). 잡음·음악 묶음은 「전사」를 꺼서 뺄 수 있습니다.
4. 「이 이름으로 전사 시작」 → 같은 묶음끼리 이어지는 말을 25초 이하 발언으로 묶어 전사합니다(화자가 바뀌는 곳에서 발언이 나뉨).
5. 검수에서 화자 이름을 누르면 **「이 발언만 / 이 묶음 전체 / 이 묶음에서 이 발언부터 끝까지」** 를 골라 바꿉니다.
   발언별로 따로 지정한 것은 묶음 이름을 바꿔도 그대로 남고, 「되돌리기」(Ctrl+Z·⌘Z)로 하나씩 되돌립니다.
   「확인 필요」에는 이름 없는 묶음 · 묶음과 덜 닮은 발언 · 다른 묶음과 비슷한 발언 · 2초 미만 발언이 먼저 나옵니다.
6. 이름을 확인했으면 **「목소리 기준 저장」** — 30초 이상 말한 사람만 이 녹음을 출처로 저장해 다음 녹음에서 추천합니다.

10-08 회의(5명, 1시간 57분)를 Plaud 이름을 숨기고 돌린 시험: 묶음 8개(한 사람이 2~3개로 나뉨 — 같은 이름을 붙이면 합쳐짐),
묶음마다 가장 많은 사람 이름을 붙였을 때 발언 시간 기준 98.1%, 말이 4분뿐인 사람도 따로 잡혔습니다.

## 쓰는 법

1. 최신 **Chrome이나 Edge**의 일반 창(시크릿 창 X)으로 주소를 엽니다.
2. (Plaud 녹음일 때) Plaud 웹/앱에서 녹음 음원(MP3)과 전사(**TXT·SRT·DOCX**, 타임스탬프·화자 표시 켜기)를 내보냅니다.
3. **「새 작업」** 에서 녹음 출처와 할 일을 고르고 음원(과 Plaud 전사) 파일을 고릅니다.
   - 전사를 고르면 전사가 녹음 어디서 끝나는지 띠로 보여줍니다.
   - 「Speaker 1」처럼 이름이 없는 화자는 실제 이름을 넣어 주세요. 이름을 넣은 사람만 목소리 기준으로 저장됩니다.
4. 처음 처리할 때 모델(약 0.9GB)을 이 사이트에서 한 번 받아 브라우저에 보관합니다.
5. 처리하는 동안 **탭을 열어 두세요.** 닫았다가 다시 열면 끊긴 구간부터 이어서 합니다.
6. **검수·내보내기** 탭에서 「확인 필요」(화자 혼재·미상·저신뢰)부터 ▶로 들어 보고 고친 뒤 **통합본 TXT** 로 받습니다.

처리 속도는 PC 성능에 따라 다릅니다. 소니 녹음의 화자 묶기는 목소리 특징만 계산하므로 전사보다 훨씬 빠릅니다. 시험(스레드 1개)에서는 음성 1분에 약 7분, 목소리 기준 만들기(같은 회의 전사 64분 분량)에 약 5분이 걸렸습니다. 스레드는 기본으로 「CPU 수 − 1」개를 쓰며, 많을수록 빨라집니다.

## 데이터와 보안

- 음원·전사·결과·목소리 기준은 **이 브라우저 안(IndexedDB·OPFS)에만** 저장됩니다. 사이트가 받아 오는 것은 화면과 모델 파일뿐이며,
  CSP(`connect-src 'self'`)로 바깥 요청을 막아 두었습니다.
- 브라우저 데이터를 지우면 함께 사라집니다. **설정·백업 → 백업 내려받기**로 음원을 뺀 데이터를 JSON으로 받아 두고,
  다른 PC·브라우저에서는 「백업 올리기」로 되살립니다.
- 목소리 기준은 개인을 식별할 수 있는 정보입니다. 필요 없어진 사람은 「목소리 기준」 탭에서 지우세요.
- 다 쓴 작업은 「음원 지우기」로 음원만 지울 수 있습니다(결과는 남습니다).

## 엔진

| | 쓰는 것 | 비고 |
|---|---|---|
| 전사 | Whisper turbo (sherpa-onnx int8 내보내기) + onnxruntime-web | 25초 이하 구간마다 30초 창으로 전사, 탐욕 디코딩. 디코더 토큰 임베딩은 행별 int8로 줄여 올림 |
| 화자 | CAM++ 목소리 특징 + 기준 맞히기 | Plaud가 이름 붙인 구간으로 사람별 기준을 만들고, 3초 창 투표로 판정(70% 이상 단일, 아니면 혼재) |
| 화자 묶기(소니) | CAM++ 3초 창 + 평균 연결 계층 묶기 | 인원 수를 정하지 않고 유사도 0.35에서 끊음, 10초 미만 묶음은 흡수, 저장된 기준과 0.6 이상이면 이름 추천 |
| 말소리 구간 | Silero VAD + 음량 맞춤 | 칸마다 앞뒤 3초 음량을 맞춰 넣음 — 10-08 회의에서 놓친 발언 414개 중 50개 → 1개(에너지 기준 5개). Silero가 거의 못 찾는 녹음(8kHz 전화 음질·큰 잡음)은 음량 기준으로 대신 |
| 전화 음질 | 대역 비 판정 | 4kHz 위가 빈 녹음(통화 녹음 등)은 목소리 특징이 서로 더 닮아 보여 묶기 기준을 0.35 → 0.45로 올림 |
| 환각 제거 | 「다음 영상에서…」류·4자 이상 반복 | 자동으로 빼고 건수만 남김 |
| 음원 | 브라우저 내장 디코더 | MP3·m4a(AAC)는 프레임 경계에서 60초씩 잘라 풀어(m4a는 프레임마다 ADTS 머리를 붙임, 긴 녹음도 메모리 안전) 16kHz로 저장 |

log-mel·fbank 계산은 `tools/ref_*.py`(파이썬 기준 구현)와 수치가 같은지 `tests/unit`에서 대조합니다.

## 개발

```bash
npm ci && npm run vendor          # onnxruntime-web을 web/vendor로
npm test                          # 단위 시험 + 가짜 엔진(?fake=1)으로 Chromium 전체 흐름
python tools/prepare_models.py <sherpa-onnx-whisper-turbo 폴더> <campplus.onnx> web/models <silero_vad.onnx>   # 실제 모델(로컬 확인용)
npm run serve                     # http://127.0.0.1:8080
```

배포는 `main`에 밀면 `.github/workflows/pages.yml`이 시험 → 모델 준비 → Pages 배포까지 합니다.
