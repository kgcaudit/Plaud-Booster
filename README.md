# Plaud 보강 작업대

Plaud 녹음의 빈 곳을 메우는 개인용 웹앱입니다. **GitHub Pages 주소를 열면 바로 쓰고, 음원과 전사는 PC 밖으로 나가지 않습니다.**
전사(Whisper turbo)와 화자 맞히기(CAM++)가 모두 브라우저 안(WebAssembly)에서 돌아갑니다.

**주소:** https://kgcaudit.github.io/plaud-booster/

| 작업 | 하는 일 |
|---|---|
| **누락 구간 보충** | Plaud 전사가 녹음 중간에 끊겼을 때, 끊긴 지점부터 녹음 끝까지 전사하고 화자를 붙입니다. |
| **지정 구간 다시 전사** | 잘못 전사된 구간(시작~끝)만 다시 전사합니다. |
| **조각 음원 화자 매칭** | Plaud에 없는 음성, 여러 파일로 나뉜 같은 회의 녹음을 전사하고 저장된 목소리 기준으로 화자를 맞힙니다. |
| **목소리 기준만 등록** | Plaud 전사(화자 이름 포함)와 음원으로 사람별 목소리 기준만 만듭니다. |

처리 결과는 검수 화면에서 구간마다 들어 보며 화자·문장을 고치고, Plaud 전사와 합친 **통합본(TXT·CSV)** 으로 내려받습니다.

## 쓰는 법

1. 최신 **Chrome이나 Edge**의 일반 창(시크릿 창 X)으로 주소를 엽니다.
2. Plaud 웹/앱에서 녹음 음원(MP3)과 전사(**TXT·SRT·DOCX**, 타임스탬프·화자 표시 켜기)를 내보냅니다.
3. **「새 작업」** 에서 유형을 고르고 음원과 전사 파일을 고릅니다.
   - 전사를 고르면 전사가 녹음 어디서 끝나는지 띠로 보여줍니다.
   - 「Speaker 1」처럼 이름이 없는 화자는 실제 이름을 넣어 주세요. 이름을 넣은 사람만 목소리 기준으로 저장됩니다.
4. 처음 처리할 때 모델(약 0.9GB)을 이 사이트에서 한 번 받아 브라우저에 보관합니다.
5. 처리하는 동안 **탭을 열어 두세요.** 닫았다가 다시 열면 끊긴 구간부터 이어서 합니다.
6. **검수·내보내기** 탭에서 「확인 필요」(화자 혼재·미상·저신뢰)부터 ▶로 들어 보고 고친 뒤 **통합본 TXT** 로 받습니다.

처리 속도는 PC 성능에 따라 다릅니다. 시험(스레드 1개)에서는 음성 1분에 약 7분, 목소리 기준 만들기(같은 회의 전사 64분 분량)에 약 5분이 걸렸습니다. 스레드는 기본으로 「CPU 수 − 1」개를 쓰며, 많을수록 빨라집니다.

## 데이터와 보안

- 음원·전사·결과·목소리 기준은 **이 브라우저 안(IndexedDB·OPFS)에만** 저장됩니다. 사이트가 받아 오는 것은 화면과 모델 파일뿐이며,
  CSP(`connect-src 'self'`)로 바깥 요청을 막아 두었습니다.
- 브라우저 데이터를 지우면 함께 사라집니다. **설정·백업 → 백업 내려받기**로 음원을 뺀 데이터를 JSON으로 받아 두고,
  다른 PC·브라우저에서는 「백업 올리기」로 되살립니다.
- 목소리 기준은 개인을 식별할 수 있는 정보입니다. 필요 없어진 사람은 「목소리 기준」 탭에서 지우세요.
- 다 쓴 작업은 「음원 지우기」로 음원만 지울 수 있습니다(결과는 남습니다).

## 엔진

| | 쓰는 것 | 비고 |
|---|---|---|
| 전사 | Whisper turbo (sherpa-onnx int8 내보내기) + onnxruntime-web | 25초 이하 구간마다 30초 창으로 전사, 탐욕 디코딩. 디코더 토큰 임베딩은 행별 int8로 줄여 올림 |
| 화자 | CAM++ 목소리 특징 + 기준 맞히기 | Plaud가 이름 붙인 구간으로 사람별 기준을 만들고, 3초 창 투표로 판정(70% 이상 단일, 아니면 혼재) |
| 환각 제거 | 「다음 영상에서…」류·4자 이상 반복 | 자동으로 빼고 건수만 남김 |
| 음원 | 브라우저 내장 디코더 | MP3는 프레임 경계에서 60초씩 잘라 풀어(긴 녹음도 메모리 안전) 16kHz로 저장 |

log-mel·fbank 계산은 `tools/ref_*.py`(파이썬 기준 구현)와 수치가 같은지 `tests/unit`에서 대조합니다.

## 개발

```bash
npm ci && npm run vendor          # onnxruntime-web을 web/vendor로
npm test                          # 단위 시험 + 가짜 엔진(?fake=1)으로 Chromium 전체 흐름
python tools/prepare_models.py <sherpa-onnx-whisper-turbo 폴더> <campplus.onnx> web/models   # 실제 모델(로컬 확인용)
npm run serve                     # http://127.0.0.1:8080
```

배포는 `main`에 밀면 `.github/workflows/pages.yml`이 시험 → 모델 준비 → Pages 배포까지 합니다.
